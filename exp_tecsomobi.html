Arquitetura de qualidade e homologação por praça

Em Orbi/TMOB, acompanhei jornadas para Vai Passe Fácil, ITAMOBI, Belém, Livramento e TOP. Levantei com Produto e Operações o que mudava entre praças, incluindo identidade visual, meios de pagamento, parametrização e regras da carteira ABT. Transformei essas diferenças em critérios de aceite, riscos, regressão e verificações antes do go-live.

AWS, dados e validadores físicos

Testei recargas da compra à utilização no validador, incluindo comunicação por MQTT, sincronização incremental por SFTP, QR, NFC/RFID e estados offline. Usei AWS Lambda, SQS, S3 e CloudWatch, consultas PostgreSQL, logs ADB/logcat e SQLite embarcado para acompanhar a jornada.

Nas investigações, liguei intenção de compra, PIX, pedido, token, arquivo incremental e uso no dispositivo. Conferi encoding, BOM e estrutura dos arquivos e repassei as consultas e o roteiro de diagnóstico a Desenvolvimento e Suporte N1/N2/N3.

  • Aplicativos e canais: conferi mensagens, saldo e pedido no app, WhatsApp e POS e comparei o retorno de cada canal com a API e o gateway de pagamento.
  • Backend e AWS: correlacionei evento, pedido e token usando PostgreSQL e CloudWatch. Kibana, Dozzle e Argo apoiaram a investigação de serviços e integrações.
  • Equipamento e contingência: validei tokenização online e offline, sincronização de recargas e permissões por arquivos incrementais, comunicação MQTT QoS 2, QR, aproximação NFC/RFID e registros de firmware.
  • Homologação e operação: levei as verificações para regressão, double check e Go/No-Go de novas versões. Em incidentes, compartilhei consultas, hipóteses e retestes com os níveis de suporte e desenvolvimento.
Redução Crítica de Falhas Operacionais
  • Reduzi falhas em campo de 8% para 0,5% liderando QA técnica no lançamento e expansão de aplicativos para novas praças/cidades (expansão geográfica)
  • Estratégia de testes cobrindo 15+ cenários críticos do fluxo completo:
    • Compra → PIX → Geração QR Code → Validação física na catraca
    • Timeout em cada etapa (5s, 10s, 30s, 60s)
    • Falha de rede durante pagamento (retry exponencial)
    • Concorrência (múltiplas compras simultâneas)
    • Estados inválidos (pagamento aprovado mas QR não gerado)
  • Garantia de estabilidade operacional no go-live em múltiplas cidades, evitando impacto em usuários finais e reduzindo chamados de suporte em 60%
Conformidade PIX em Larga Escala
  • Validei conformidade de 50K+ pagamentos PIX mensais garantindo:
    • Idempotência: Prevenção de pagamentos duplicados mesmo com retry do usuário (validação de chave de idempotência única por transação)
    • Ausência de duplicidade: Validação de transações únicas por chave transacional, impedindo cobranças múltiplas pelo mesmo serviço
    • Tratamento de timeout: Cenários de 5s, 10s, 30s, 60s com retry exponencial (backoff: 2s, 4s, 8s) e circuit breaker após 3 falhas consecutivas
    • Conciliação financeira: Zero inconsistências transacionais detectadas através de queries SQL validando cadeia completa (intenção → pagamento → ordem → token → arquivo incremental)
    • Validação de estados: Máquina de estados completa (pendente → processando → pago → expirado → cancelado → reembolsado)
  • Integração com PSP (Payment Service Provider) e compliance com regulamentações do Banco Central (SPI - Sistema de Pagamentos Instantâneos)
  • Monitoramento proativo com alertas configurados no CloudWatch para taxas de erro > 1%, latência > 10s, disponibilidade < 99%
Framework de Automação API - Eliminação de Dependências
  • Desenvolvi framework de automação API no Postman eliminando 6+ dependências manuais que atrasavam execução de testes:
    1. Sites geradores de CPF → Algoritmo validador de CPF implementado (cálculo dos dígitos verificadores)
    2. Sites geradores de email → Geração dinâmica padronizada (padrão: qa_test_{timestamp}@mailsac.com)
    3. Provedores de email temporário → Integração com Mailsac API para criação automática de caixas de entrada descartáveis
    4. Criação manual de massa de teste → Scripts automatizados de cleanup (DELETE em cascata após execução)
    5. Validação manual de recebimento de email → Polling automático de inbox (intervalo de 2s, timeout 60s)
    6. Extração manual de códigos de confirmação → Regex para extração de OTP (/\d{6}/ para código de 6 dígitos)
  • Resultado quantificado: Redução de setup de massa de testes de 2-4 minutos para 8 segundos (melhoria de 1500%-3000%)
  • Beneficiara 12+ pessoas (QAs, Devs, Suprote e ETC)
  • Desdobramento posterior: a partir desse aprendizado inicial, continuei em casa um laboratório próprio de automação mobile, expandindo o piloto para uma arquitetura mais ampla.
TMobi Automation Platform

Comecei com um piloto para lidar com a manutenção dos testes mobile na operação. Depois, desenvolvi por conta própria um laboratório em Ruby para explorar telas, propor cenários com IA e registrar a execução no Android.

No laboratório, a exploração captura imagens e XML da interface. As imagens alimentam a geração de casos em CSV, e o identificador CT-ID permite atualizar o mesmo caso no Notion. Os testes em Appium verificam o comportamento do app, com evidências de execução reunidas no Allure.

Estrutura arquitetural

O projeto foi organizado em camadas com core de driver/configuração, helpers reutilizáveis, pages por domínio funcional, specs RSpec, módulos dedicados para IA, crawler, dashboard, notificações e load tests.

Esse desenho reduziu acoplamento, facilitou expansão do catálogo de telas e permitiu escalar o uso da automação para além do time de QA, conectando engenharia, operações e gestão de qualidade em um fluxo único.

Ferramenta Smart_Locator - Redução de Manutenção
  • Criei ferramenta interna para automação mobile que reduziu manutenção de locators em 70%
  • Funcionalidades implementadas:
    • Geração automática de XPath otimizados (evita caminhos absolutos frágeis)
    • Fallback strategies em cascata:
      1. 1º: Tentar localizar por ID (mais rápido e estável)
      2. 2º: Tentar por accessibility label (Android: contentDescription, iOS: accessibilityLabel)
      3. 3º: Tentar por texto visível (text() ou label)
      4. 4º: Tentar por XPath relativo (irmãos, pais, filhos)
    • Cache de elementos para performance (redução de 30% no tempo de execução de suites)
    • Healing automático de locators quebrados (tentativa de reconstrução baseada em contexto)
    • Logging detalhado para debug (qual estratégia funcionou, tempo de busca, hierarquia tentada)
  • Adotada por 3 squads após apresentação técnica em Tech Talk interno
Redução de MTTR - Análise de Causa Raiz N2/N3
  • Reduzi MTTR (Mean Time To Resolution) de incidentes de 4 horas para 45 minutos
  • Metodologia de troubleshooting:
    • Análise de causa raiz (N2/N3) correlacionando logs entre múltiplas camadas:
      • AWS CloudWatch: API Gateway (validação de requests/responses, status codes, latência), Lambda (execução de funções, errors, timeouts), DynamoDB (queries, scans, throughput)
      • Kibana: Serviços backend Java/Node.js (stack traces, exceptions, business logic errors, SQL queries lentas)
      • Duzzle: Containers Docker em EC2 (logs de aplicação, health checks, métricas de CPU/memória)
    • Identificação de padrões anômalos (spike de erros 500, latência P95 > 5s, dead letter queue crescendo)
    • Rastreamento de request ID único através de toda a stack (distributed tracing)
  • Criação de runbooks de investigação documentados no Confluence:
    • Checklist passo a passo para cada tipo de incidente (pagamento falhou, QR Code não gerado, catracas offline, etc.)
    • Queries específicas de CloudWatch Logs Insights
    • Dashboards Kibana pré-configurados por tipo de erro
    • Contatos de escalação por severidade (P1: CTO + Eng Manager, P2: Tech Lead, P3: Squad)
